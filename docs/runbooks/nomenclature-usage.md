# Статистика подбора номенклатуры

`ONEC_USAGE_MCP_CONFIG` — приватный JSON в `.env` сервера: ключ — id компании ScanFlow, значение — `{ "url": "http://onec-host:6003/mcp", "token": "..." }`. Для GitHub Actions та же строка хранится в секрете репозитория `ONEC_USAGE_MCP_CONFIG`; выкладка переносит её в серверный `.env`. Для отключения — `{}`. Секреты не добавлять в git или описание задачи.

Источник должен быть MCP Toolkit той базы, из которой компания выгружает каталог. Указывать соответствие явно; общий источник для всех компаний не используется. Адрес должен быть доступен с сервера ScanFlow. Перед перезапуском при выкладке `dist/scripts/check-onec-usage.js` проверяет каталог и настоящий запрос к каждому назначенному источнику. Действующий `1c-mag` в личном конфиге Codex относится к MAG; по инструкции интеграции ScanFlow это база компании zakupki (на проде id 3). Локальная БД отличается от прода, поэтому id нельзя переносить без проверки каталога.

После выкладки владелец компании проверяет `GET /api/onec/usage?guids=<GUID-из-каталога-компании>` со своим `X-API-Key`. Без `guids` проверяются первые 10 позиций. Ответ содержит только доступность, дату проверки, названия и счётчики; токен и URL не возвращаются. Чужой каталогу GUID не принимается. Даже администратор не может выбрать чужую компанию для этого запроса. У базы MAG контрольная позиция `d40b6f5c-6bb6-11f1-bc9e-00155d647d01` (бекон) на 16.10.2026: 2 спецификации, 3 проведённых прихода.

Проверка выполняется только при нескольких подходящих вариантах. Все спецификации без пометки удаления учитываются независимо от даты и признака «Недействителен» (требование — вся история). Приходы — все проведённые, без пометки удаления. Результат на GUID кэшируется на час отдельно для каждой компании и источника. Ошибка 1С не считается нулём: остаётся обычный подбор с предупреждением в объяснении; повторная попытка допускается через минуту. Изменение источника сразу создаёт отдельный кэш.

Уже отправленные накладные не пересопоставляются. Чтобы проверить сохранённую накладную — обычный повторный подбор / подбор ИИ: выбор человека и правила поставщика сохраняют приоритет. В карточке под позицией видна первая фраза объяснения, раскрытие показывает сравнение всех кандидатов и дату проверки. Применение и откат предложений очереди сохраняют объяснение.
