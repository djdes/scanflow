# Синхронизация каталога и статистика подбора номенклатуры по MCP

`ONEC_USAGE_MCP_CONFIG` — приватный JSON в `.env` сервера: ключ — id компании ScanFlow, значение — настройки HTTP-сервиса `feenlace/mcp-1c` (`{ "url": "http://onec-host/mcp-1c/hs/mcp-1c", "user": "Админ" }`) или JSON-RPC MCP Toolkit (`{ "url": "http://onec-host:6003/mcp", "token": "..." }`). Для GitHub Actions та же строка хранится в секрете репозитория `ONEC_USAGE_MCP_CONFIG`; выкладка переносит её в серверный `.env`. Для отключения — `{}`. Секреты не добавлять в git или описание задачи.

На боевом сервере ScanFlow компании привязаны к базам 1С:УНФ следующим образом:
- компания `1` (`admin`) — база **1С MAG** (`/mcp-1c/hs/mcp-1c`, пользователь `Админ`);
- компания `3` (`zakupki`) — база **1С SUB** (`/mcp-1c-subprod/hs/mcp-1c`, пользователь `Директор`).

При наличии `user` в записи компании модуль `src/integration/onecCatalogMcp.ts` выполняет прямую полную синхронизацию справочника `Справочник.Номенклатура` (все рабочие категории и папки `ЭтоГруппа = Истина`, кроме помеченных на удаление и архивных категорий `Списанное`, `Резерв Сезонное`, `SubExpress-Архив`, `РЕЗЕРВ`, `ПРОРАБОТКА`):
- автоматически при запуске сервера и каждые 30 минут по расписанию;
- при каждой выкладке через `dist/scripts/check-onec-usage.js`;
- после создания/проведения документа в 1С (`POST /api/onec/exchange/invoices/:id/status`) и при опросе `sync-flag`;
- вручную кнопкой «Синхронизировать с 1С» во вкладке «Справочник 1С» (`POST /api/nomenclature/sync-mcp`).
Если для компании настроен MCP-источник каталога, вызовы `DELETE /api/onec/exchange/nomenclature` от старой внешней обработки `.epf` перехватываются и не очищают каталог (вместо этого запускается полная синхронизация по MCP).

После выкладки владелец компании проверяет `GET /api/onec/usage?guids=<GUID-из-каталога-компании>` со своим `X-API-Key`. Без `guids` проверяются первые 10 позиций. Ответ содержит только доступность, дату проверки, названия и счётчики; токен и URL не возвращаются. Чужой каталогу GUID не принимается. Даже администратор не может выбрать чужую компанию для этого запроса. У базы MAG контрольная позиция `d40b6f5c-6bb6-11f1-bc9e-00155d647d01` (бекон) на 16.10.2026: 2 спецификации, 3 проведённых прихода.

Проверка выполняется только при нескольких подходящих вариантах. Все спецификации без пометки удаления учитываются независимо от даты и признака «Недействителен» (требование — вся история). Приходы — все проведённые, без пометки удаления. Результат на GUID кэшируется на час отдельно для каждой компании и источника. Ошибка 1С не считается нулём: остаётся обычный подбор с предупреждением в объяснении; повторная попытка допускается через минуту. Изменение источника сразу создаёт отдельный кэш.
