# Постоянная очередь распознавания

`POST /api/upload` и входящие загрузки подтверждают приём (`202`, `job_id`) только после записи файла и задания в MySQL. Браузер хранит фото в IndexedDB до этого подтверждения. При сетевой ошибке, тайм-ауте или временной ошибке сервера отправка повторяется; после закрытия страницы она продолжится при следующем открытии ScanFlow в том же браузере. Если локальное хранилище недоступно, интерфейс просит дождаться приёма сервером.

Задания `recognition_jobs` не удаляются из-за ошибок. Повторные попытки идут через 30 секунд с увеличением интервала до часа, без ограничения числа попыток. Недоступность GPT оставляет фото в очереди; XML может обрабатываться отдельно. Раздел загрузки показывает сохранённые задания, причину сбоя, следующую попытку и ручной повтор. На главной есть ссылка на ожидающие задания. API возвращает только задания текущего владельца.

Один worker берёт задания с блокировкой в БД и пятиминутной арендой, обновляемой каждые 30 секунд. После аварии аренда истечёт, и задание возобновится. Повтор работает с той же накладной; хеш файла исключает повторное создание при повторной отправке. Ручное распознавание и пакетная обработка очереди 1С согласованы с worker внутри процесса; прод должен запускать один процесс приложения.

При запуске и затем раз в минуту добавляются старые незавершённые накладные и проверяется inbox. Имя нового файла содержит владельца, поэтому файл, сохранённый перед сбоем БД, можно безопасно принять позже. Прямое помещение файлов в inbox без такого имени сохраняет прежнюю привязку к оператору платформы. Отправленные, подтверждённые и оплаченные документы автоматически не перераспознаются. Явное удаление накладной отменяет её задание; удаление во время обработки запрещено.

Исходные файлы в inbox/processed/failed и таблицы очереди необходимо включать в резервное копирование. Очередь не восстанавливает фотографию, которая не дошла до сервера и не сохранилась в браузере. Отсутствующий исходник остаётся видимой ошибкой с просьбой загрузить фото повторно.

Диагностика: `GET /api/recognition-queue` (активные задания), `GET /api/recognition-queue/:id` (квитанция), `POST /api/recognition-queue/:id/retry` (немедленная повторная попытка). Это очередь распознавания фотографий; существующая очередь проверки и отправки документов в 1С остаётся отдельным процессом.

## Ручное объединение страниц

В меню «⋯» списка или карточки накладной выберите объединение страниц. Можно искать другую карточку по номеру, поставщику или `#ID`; совпадение распознанных номеров больше не является условием появления выбора. Документ с номером предлагается основной карточкой, его можно сменить до подтверждения. Перед сохранением показаны направление объединения и итог документа (максимум итогов страниц, а не их сумма).

Объединение переносит товары, фотографии, области скана и исходное распознавание одной транзакцией, сохраняет переход со старой ссылки и требует повторной сверки страниц. При ошибке БД изменения откатываются. Разные известные номера/даты/ИНН, XML, активная очередь и платёжные документы блокируют объединение.
