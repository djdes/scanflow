# Единый API помощника по товарам ScanFlow, версия 1

Этот контракт позволяет подключить к ScanFlow своего шеф-бота, диспетчера или другого помощника. Конкретный бот не является частью ScanFlow и не обязателен для работы: без подключения используется обычный справочник 1С. Поиск, консультация и запоминание работают через backend ScanFlow, браузер не вызывает API бота напрямую.

Реализация: `src/integration/productAssistant.ts`, `src/api/routes/productAssistant.ts`. Настройки: **Профиль → Помощник по товарам**. У каждой компании свои название, базовый адрес API, токен и переключатель подключения. В текущей модели ScanFlow компания определяется `users.id` / `owner_user_id`, а не ролью `admin`. Подключение MAG не используется для других компаний.

## Подключение и защита данных

1. Реализуйте маршруты ниже на своём HTTP-сервисе. Базовый адрес включает выбранный вами префикс, например `https://bot.example/api/scanflow`.
2. Выпустите отдельный Bearer-токен для этого подключения. Он должен разрешать доступ только к каталогу и знаниям соответствующей компании. Не используйте токен администрирования или управления Telegram.
3. Администратор сервера ScanFlow добавляет origin сервиса (схема, хост, порт; без пути) в `PRODUCT_ASSISTANT_ALLOWED_ORIGINS`, через запятую, и перезапускает backend. Это ограничивает сетевые назначения прокси. HTTPS рекомендуется; HTTP допускается для явно разрешённой локальной сети/VPN. Переадресации не поддерживаются.
4. Укажите название, полный базовый адрес API и токен в профиле нужной компании, включите подключение, сохраните и нажмите «Проверить».

Токен принимается однократно через HTTPS, хранится в `product_assistant_connections` зашифрованным AES-256-GCM с отдельным назначением ключа для владельца. Нужен серверный `JWT_SECRET` длиной не менее 32 символов. В API чтения настроек возвращается только `token_set`; токен не возвращается браузеру и не сохраняется в localStorage. Пустое поле токена при сохранении означает «оставить прежний». При смене адреса требуется новый ввод токена. Удаление подключения удаляет его настройки и секрет, но не удаляет знания в стороннем сервисе.

Пример серверного окружения для шеф-бота MAG (выберите адрес, доступный **с backend ScanFlow**, а не только с компьютера пользователя):

```dotenv
PRODUCT_ASSISTANT_ALLOWED_ORIGINS=http://10.9.1.3:18091,http://192.168.33.214:18091
```

В профиле MAG полный адрес: `http://10.9.1.3:18091/api/chef/scanflow` либо LAN-вариант. Токен — `CHEF_SCANFLOW_API_TOKEN` из приватного окружения шефа. Этот бот обслуживает только `company_id=1`; его нельзя подключать вместо бота другой компании. Для других компаний задаются их собственные сервисы. Исходное описание шефа: `C:\www\hermes-chef-bot\docs\SCANFLOW_API.md`.

### Шеф SUB / Subexpress

Для пользователя **zakupki**, `company_id=3`, доступен отдельный совместимый бот:

| Где работает backend ScanFlow | Базовый адрес API SUB |
| --- | --- |
| На сервере BSQL | `http://127.0.0.1:18092/api/chef/scanflow` |
| На другом сервере с доступом в VPN | `http://10.9.1.3:18092/api/chef/scanflow` |
| В локальной сети BSQL | `http://192.168.33.214:18092/api/chef/scanflow` |

`127.0.0.1` означает машину backend: для production ScanFlow на отдельном сервере нужен VPN/LAN-маршрут до BSQL. На BSQL разрешите origin `http://127.0.0.1:18092` в `PRODUCT_ASSISTANT_ALLOWED_ORIGINS`, в профиле **zakupki** задайте полный адрес с префиксом и отдельный токен `SUB_CHEF_SCANFLOW_API_TOKEN` из приватного окружения `C:\www\sub-chef-bot\.env`.

У самого SUB-бота также должен быть настроен **другой** ключ — `SCANFLOW_SUB_API_KEY`, принадлежащий upstream-пользователю `zakupki` на ScanFlow. Входящий Bearer-токен не заменяет этот ключ. Пока `/status` сообщает `upstream_configured=false`, HTTP-сервис доступен, но каталог не загружен и поиск возвращает `503`. «Проверить» в профиле показывает это состояние отдельно от успешной авторизации. Консультации и запоминание станут доступны после первой синхронизации. Для SUB используются исходные единицы каталога (`all_kg=false`), автоматического перевода в килограммы этим подключением нет.

Документация: `C:\www\sub-chef-bot\docs\SCANFLOW_API.md`; OpenAPI 3.1: `C:\www\sub-chef-bot\docs\scanflow-openapi.json` или авторизованный `GET /api/chef/scanflow/openapi.json`.

Подключение production проверено 30.10.2026: backend `scanflow.ru` видит SUB по LAN-адресу `http://192.168.33.214:18092`, отдельный SSH-туннель не требуется. Ключ upstream взят из действующей учётной записи `zakupki` с проверкой `/api/profile`; значение хранится только в приватном `.env` SUB-бота. Первая синхронизация и поиск по каталогу завершились успешно. Это настройка компании 3, не адрес помощника по умолчанию для всех пользователей.

Поиск отправляет название и поставщика строки; консультация дополнительно передаёт вопрос, исходное количество/единицу, номера накладной и строки, кандидатов. Фотографии не передаются. `actor_id`, `company_id` и контекст формирует доверенный backend по авторизованному пользователю и принадлежащей ему строке. Не принимайте произвольную компанию из браузера. Помощник обязан проверять принадлежность диалогов и запросов к `actor_id` и каталога к компании токена. Знания компании можно использовать в её Telegram/MAX-ботах; доступ между разными компаниями разрешать нельзя.

## Общие правила протокола

- UTF-8 JSON. Все пути ниже относительно настроенного базового адреса.
- `Authorization: Bearer <токен>` на каждом запросе. Не передавайте секрет в URL.
- ScanFlow отправляет `X-ScanFlow-Assistant-Version: 1` и `X-ScanFlow-Company-Id: <users.id>`. Рекомендуется возвращать `protocol_version: 1` в ответах. Отсутствие поля допускается для совместимости с существующим шефом; другая явно указанная версия отклоняется.
- Успешный ответ содержит `ok: true`. Ошибка: не-2xx и `{"ok":false,"error":"машинный_код"}`. Не возвращайте токены в ошибках.
- `actor_id` — строка `scanflow-user-<users.id>`, до 120 символов. `company_id` — соответствующий положительный ID компании ScanFlow.
- UUID товаров соответствуют каталогу 1С этой компании. Папки, удалённые и архивные позиции исключаются. ScanFlow дополнительно проверяет GUID по своему актуальному каталогу и отметкам «Не это».
- `request_id` и `session_id` — 32 шестнадцатеричных символа. Состояния запросов: `queued`, `running`, `completed`, `failed`.
- POST принимает `Idempotency-Key`: 1–160 символов из `A–Z a–z 0–9 . _ : -`. Область уникальности — токен компании + `actor_id`. Повтор того же тела возвращает тот же запрос; то же значение с другим телом даёт `409`.
- HTTP-запрос должен завершиться за 15 секунд. Долгие операции выполняются в очереди и возвращают `202`. Опрос — раз в 2 секунды, до 6 минут. По потерянному ответу POST клиент повторяет исходное тело и ключ. По принятому запросу — повторяет GET состояния, не создаёт новую работу. Новый вопрос после `failed` получает новый ключ.

## 1. Проверка подключения

```http
GET /status
Authorization: Bearer <токен>
```

```json
{"ok":true,"protocol_version":1,"company_id":1,"catalog_synced_at":1793352000,"last_sync_error":null}
```

`company_id` обязателен: сервис возвращает фактическую компанию Bearer-токена, а не копирует полученный заголовок. Дополнительные поля разрешены. ScanFlow проверяет этот ID при включении подключения и перед передачей данных строки: несовпадение блокирует вызов поиска/чата. Это позволяет не подключить шефа MAG к другой компании по ошибке. Это проверка интеграции и авторизации, а не публичный healthcheck. Текущее подключение проверяется через `GET /api/product-assistant/status` ScanFlow.

## 2. Быстрый поиск похожих и привычных товаров

```http
GET /products/search?q=батон&limit=10&scanned_name=Батон%20нарезной&supplier=Хлебозавод
```

`q` обязателен, 1–150 символов; `limit` — 1–30. `scanned_name` и `supplier` необязательны, до 255 символов. Кодируйте параметры через `URLSearchParams` или эквивалент.

```json
{
  "ok": true,
  "protocol_version": 1,
  "query": "батон",
  "total": 1,
  "catalog_synced_at": 1793352000,
  "products": [{
    "onec_guid": "492b0be3-9b24-11ee-bc6f-00155d647d01",
    "name": "Батон Нарезной",
    "code": "НФ-00003588",
    "unit": "кг",
    "score": 1050.2,
    "times_selected": 80,
    "confirmed": true,
    "matching_aliases": [{"scanned_name":"Батон нарезной","confirmed":true,"source":"knowledge","times_selected":80}]
  }]
}
```

Пример условный. `score` — относительный рейтинг, не вероятность; `times_selected` — частота реального использования/выбора, не число обращений к боту. Нулевой счётчик допустим. `matching_aliases` всегда массив; `source=knowledge` означает выбор из общей базы знаний этой компании. `confirmed` означает подтверждение человеком.

Поиск объединяет похожие названия каталога, названия из накладных, подтверждённые и частые выборы, включая привычные варианты у данного поставщика. Точные подтверждённые варианты имеют приоритет. Отметки «Не это» исключают товар для исходной строки. Вызов не запускает модель и ничего не записывает.

## 3. Консультация по строке

```http
POST /chat
Content-Type: application/json
Idempotency-Key: invoice-879-row-3-question-1
```

```json
{
  "actor_id": "scanflow-user-1",
  "company_id": 1,
  "message": "Какую позицию выбрать и как пересчитать количество?",
  "auto_learn": false,
  "context": {
    "scanned_name": "Батон нарезной 0.4 кг",
    "supplier": "Хлебозавод",
    "invoice_id": 879,
    "row_no": 3,
    "quantity": 80,
    "unit": "шт",
    "candidate_guids": ["492b0be3-9b24-11ee-bc6f-00155d647d01"]
  }
}
```

`message` — 1–8000 символов. Строки контекста — до 255; кандидатов — до 30 UUID. Числа контекста конечные и неотрицательные. Неизвестные количество, единицу и номер строки пропускайте вместо `null`: это совместимо со строгой схемой SUB API. Допускаются `pack_size` и `pack_unit`, только если фасовка явно известна; интеграция ScanFlow не выводит их из коэффициента пересчёта и не выдумывает. В следующем сообщении передайте тот же `session_id` на верхнем уровне и актуальный контекст.

Ответ — общий конверт `202`, описанный ниже. После завершения `result`:

```json
{
  "answer": "Выберите **Батон Нарезной**. 80 шт × 0,4 кг = **32 кг**.",
  "match": {"onec_guid":"492b0be3-9b24-11ee-bc6f-00155d647d01","mapped_name_1c":"Батон Нарезной","code_1c":"НФ-00003588","unit":"кг","confidence":0.99,"reason":"Совпадает вид и фасовка","approved":false},
  "learning": {"status":"suggestion_only"}
}
```

`match` может быть `null`; `answer` — Markdown. ScanFlow отображает безопасное подмножество Markdown (жирный текст и встроенный код), HTML и ссылки не исполняются. Для выбора используется только структурированный GUID, а название повторно берётся из каталога компании.

**Консультация не меняет строку накладной.** Интерфейс отправляет `auto_learn=false`: предложение сначала проверяет человек. Даже при явно разрешённом другим клиентом `auto_learn=true` сервис может сохранять только неподтверждённые предложения; UUID должен существовать в активном каталоге, подтверждённое правило и «Не это» имеют приоритет. Уверенность модели сама по себе не является подтверждением человека.

## 4. Запоминание ручного выбора

```http
POST /mappings
Content-Type: application/json
Idempotency-Key: invoice-879-row-3-selection-1
```

```json
{
  "actor_id": "scanflow-user-1",
  "company_id": 1,
  "scanned_name": "Батон нарезной 0.4 кг",
  "onec_guid": "492b0be3-9b24-11ee-bc6f-00155d647d01",
  "supplier": "Хлебозавод"
}
```

Вызывается только после явного выбора пользователя и сохранения позиции в строке, если пользователь оставил включённым «Запоминать мой выбор». Это относится как к выбору из подсказок, так и из обычного каталога. Автоматический ответ модели этим маршрутом не подтверждают. Неизвестный товар, папка и «Не это» отклоняются; запреты автоматически не снимаются этим API.

Ответ — `202`, `kind=confirm`. После обработки `result={"status":"synced|pending|known|conflict|rejected","entry":{...}}`. `synced` означает успешное сохранение; `pending` — надёжную локальную запись с очередью синхронизации; `known` — такое правило уже есть. Конфликт требует решения человека. Подтверждённые варианты доступны быстрому поиску и общей базе знаний бота. Общей является база **данной компании**, не база всех пользователей ScanFlow.

Если запись в общую базу не удалась, локальный выбор строки сохраняется. ScanFlow сообщает об этом отдельно; пользователь может повторить отправку или снять переключатель запоминания. Сервис обязан сохранять очередь и идемпотентность после рестарта. Если сервис записывает правила обратно в ScanFlow, использовать отдельный API-ключ этой компании и штатные `/api/mappings` и `/api/mappings/:id/confirm`; не создавать дубли и не заменять более свежие ручные решения.

## 5. Общий конверт очереди и опрос

```json
{
  "ok": true,
  "protocol_version": 1,
  "request_id": "0123456789abcdef0123456789abcdef",
  "session_id": "abcdef0123456789abcdef0123456789",
  "kind": "chat",
  "status": "queued",
  "result": null,
  "error": null,
  "created_at": 1793352000,
  "completed_at": null,
  "poll_url": "/api/scanflow/requests/0123456789abcdef0123456789abcdef?actor_id=scanflow-user-1"
}
```

```http
GET /requests/0123456789abcdef0123456789abcdef?actor_id=scanflow-user-1
```

Ответ `200` — тот же конверт, с текущим состоянием. `completed` содержит `result`; `failed` — `error` с безопасным кодом. HTTP `200` означает найденную запись, а не успешное выполнение работы. Чужой `actor_id` возвращает `404`. ScanFlow конструирует адрес опроса сам и не переходит по присланному `poll_url`.

`learning.status` для консультации может быть `synced`, `pending`, `known`, `conflict`, `suggestion_only`, `not_requested`, `rejected`, `no_structured_match`. При `auto_learn=false` запись нового правила не выполняется.

## Ошибки и приёмка другого бота

HTTP: `400` — некорректный запрос; `401` — токен; `403` — компания токена; `404` — чужой/неизвестный диалог или запрос; `409` — конфликт либо другой payload с тем же ключом; `429` — очередь заполнена; `503` — сервис не готов. Backend ScanFlow не передаёт наружу содержимое ошибок с секретами; ошибка авторизации стороннего бота отображается как ошибка подключения, а не завершение сессии пользователя ScanFlow.

Перед подключением проверьте:

- Без настроек ни один запрос к чужому/дефолтному боту не отправляется; две компании с разными ботами получают только свои данные.
- Поиск возвращает частый подтверждённый выбор и исключает «Не это»; сбой бота не блокирует обычный каталог.
- Чат проходит `202 → queued/running → completed|failed`; повтор после обрыва не создаёт новую работу; следующий вопрос сохраняет `session_id`.
- Ручной выбор сохраняется в общей базе, предложение модели не подтверждается автоматически. Конфликт и задержка синхронизации видны пользователю.
- После рестарта не теряются принятые задания; токен отсутствует в выдаче настроек, логах, URL и истории браузера.
