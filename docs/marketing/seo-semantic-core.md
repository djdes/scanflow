# ScanFlow — семантическое ядро

> Этот документ — основной источник правды для содержания блога и meta-тегов.
> Обновляется при добавлении новых статей или ребалансировке ключей.
> Если правишь — синхронизируй также `public/blog/articles.json` и meta-теги
> соответствующих страниц.

## Целевая аудитория

Владельцы и бухгалтеры малого/среднего B2B (продуктовый ритейл, опт, общепит)
на 1С:Управление нашей фирмой (УНФ), которые сейчас вручную перебивают
полученные от поставщиков накладные в учётную систему.

## Запросы, которые НЕ берём на этом этапе

Эти темы выглядят релевантными, но не являются нашим продуктом — преследовать
их в блоге значит размывать релевантность ScanFlow:

- `1С Бухгалтерия` — мы работаем только с УНФ.
- `ЕГАИС` / `алкогольный учёт` — отдельная подсистема, мы её не касаемся.
- `маркировка` (Честный знак, "Меркурий") — отдельный регуляторный домен.
- `ЭДО` (электронный документооборот, Диадок/СБИС) — мы не оператор ЭДО.

## LSI / семантические соседи

Слова, которые должны естественно появляться в текстах блога для подтверждения
релевантности (без перенасыщения):

накладная, поставщик, ИНН, номенклатура, артикул, единица измерения, НДС,
остатки, приход, ОКВЭД, ИП, ООО, бухгалтерия, учёт.

## Чек-лист при добавлении новой статьи

1. Определить целевой кластер (новый или существующий?).
2. Подобрать главный + 2-3 сопутствующих ключа, оценить частотность через
   Wordstat/Bukvarix/key.so.
3. Прописать в этот документ строку таблицы (или дополнить существующий
   кластер).
4. Добавить запись в `public/blog/articles.json` со slug, title, description
   (140-160 символов), tags, date, readingMinutes, ogImage.
5. Создать `public/blog/<slug>.html` по образцу существующих статей.
6. Обновить матрицу перелинковки и проставить 2-3 related-ссылки внутри
   статьи и в footer-разделе.
7. После деплоя — рестарт сервера, чтобы обновились in-memory кеши
   `landingHtmlCache` и `listingHtmlCache` (см. `src/api/server.ts`).
