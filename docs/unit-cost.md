# Цена расходной единицы

Для упаковок показывается отдельная аналитическая цена: количество упаковок × число единиц в упаковке; сумма строки ÷ полученное количество. Например, 30 рулонов по 2000 этикеток за 53550 ₽ дают 60000 этикеток по 0,8925 ₽. Результат не округляется до копейки перед дальнейшими расчётами.

Количество упаковок берётся из `raw_quantity/raw_unit`, когда они есть: пересчёт учётного количества в килограммы не должен менять число рулонов. Сумма — текущая сумма строки с тем же режимом НДС. Если суммы нет, используется исходная цена × исходное количество. Накладная, платёж и данные для 1С остаются в учётных единицах.

Автоматическое предложение требует явного количества штук/листов/пар в названии упаковки или этикеток. Размеры 60×120, метры риббона, диапазоны, альтернативные количества и неоднозначные вложенные упаковки не используются. Явное «рядов 2 по 2000 шт» означает 4000 единиц. При неопределённости человек вводит число в окне расчёта.

Предложения появляются на главной странице накладных, в том числе для уже загруженных документов. Ссылка содержит `?item=<id>` и выделяет строку. Страница обновляет уведомления раз в минуту. «Скрыть» подтверждает только увиденную версию конкретного расчёта; изменение исходных данных возвращает уведомление. Пагинация по ID не ограничивает уведомления произвольной датой.

Только «Запомнить для этого товара» создаёт правило. Ключ: компания, поставщик (ИНН или нормализованное имя), полное наименование с размерами/фасовкой, исходная единица. Каталожный GUID не требуется. Новая поставка использует коэффициент, но своё количество и свою сумму. Из окна расчёта можно отключить правило. Подтверждение защищено токеном исходных данных и текущей формулы; сохранение и запись в историю выполняются в одной транзакции.

Формула — проверяемый положительный целочисленный коэффициент до 1 млрд и одна из разрешённых единиц. Произвольный код и выражения не выполняются. Уведомления локальные для приложения; внешние рассылки не создаются.
