# Меню действий накладной + прочитано/непрочитано + «оплатили сами» — design

- **Дата:** 2026-07-23
- **Статус:** согласован, к реализации
- **Повод:** в списке накладных ✕ (удалить) — единственное строковое действие. Нужно: (1) собрать действия в компактное меню-шестерёнку; (2) видеть, какие накладные ещё не смотрели (непрочитанные); (3) помечать накладные, которые оплатили вне сервиса, чтобы они не висели как «не оплачено».

## 1. Модель данных (миграция 55, аддитивная, идемпотентная)

Две новые колонки в `invoices` через `hasColumn`-guard + `ALTER TABLE ADD COLUMN` (как миграции 2/4/28 — аддитивно, без DROP/ALTER существующих):

- `read_at DATETIME NULL` — момент первого прочтения; `NULL` = непрочитанная.
- `paid_externally TINYINT(1) NOT NULL DEFAULT 0` — оплачено вне сервиса (наличные/своя карта/etc.).

**Бэкфилл:** всем существующим строкам `read_at = COALESCE(recognized_at, created_at)` — стартуют прочитанными, чтобы не завалить пользователя сотнями «непрочитанных». Новые накладные создаются с `read_at = NULL` (в `create()` колонку не заполняем).

## 2. Меню-шестерёнка ⚙ (вместо ✕)

В колонке действий вместо `btn-icon-danger` ✕ — кнопка ⚙, открывающая маленькое выпадающее меню (позиционируется у строки, закрывается по клику-вне и Esc, `event.stopPropagation()` чтобы не срабатывал `onclick` строки → переход в деталь). Пункты:

1. **Прочитано / Непрочитано** — тумблер по `read_at`.
2. **💵 Оплатили сами / Снять отметку** — тумблер по `paid_externally`.
3. **🗑 Удалить** (красный) → существующая модалка `showConfirm(...)` (её уже вызывает `deleteInvoice`; переиспользуем как есть — отдельного подтверждения городить не надо).

Кнопку «→ 1С» оставляем отдельной первичной кнопкой рядом; в меню её не переносим.

## 3. Прочитано/непрочитано (новая фича)

**Отображение:** непрочитанная строка — **жирный шрифт + лёгкая заливка фона** (CSS-класс `tr.unread`, тема-aware через переменные/`prefers-color-scheme`). Условие в рендере списка: `!inv.read_at`.

**Пометка прочитанной:**
- (а) при открытии детали накладной — сервер в `GET /api/invoices/:id` идемпотентно ставит `read_at = NOW()`, если он `NULL` **и** запрашивает владелец накладной (`owner_user_id = req.userId` или `owner_user_id IS NULL`); чужой/админский просмотр read-состояние компании не трогает;
- (б) кнопкой «Прочитано» в меню.

**Снять прочтение:** кнопка «Непрочитано» ставит `read_at = NULL`.

**Endpoint:** `POST /api/invoices/:id/read` с телом `{ read: boolean }` — owner-scoped, доступен любому юзеру аккаунта (не admin-only, это персональная UX-операция компании). `read:true` → `read_at = NOW()` (если уже стоит — не перетираем), `read:false` → `read_at = NULL`.

## 4. «Оплатили сами» (булев флаг)

**Endpoint:** `POST /api/invoices/:id/paid-externally` с телом `{ value: boolean }` — owner-scoped, любой юзер аккаунта. Ставит/снимает `paid_externally`.

**Колонка СБЕР** (`_sberCell`): при `paid_externally=1` показываем **💵 Сами** (серый, `title="Оплачено вне сервиса"`) — приоритетно, **до** проверок `sber_overdue` и `sber_payment_status` (оплаченная сами накладная не бывает «просроченной» и «без платежа»).

**Исключение из всех платёжных поверхностей** — единым условием `paid_externally = 0`:

| Точка | Файл | Эффект |
|---|---|---|
| `sberOverduePredicate(days)` | `invoiceRepo.ts:34` | Снимает и метку `⏰ Nд+` в списке, и Telegram-cron-алерт (предикат общий для SELECT и WHERE). |
| `sberUnsent` (карточка «без платежа за 30 дней») | `invoices.ts:207` | Убирает из счётчика/суммы бэклога. |
| `forecast` (обязательства/прогноз) | `operationsRepo.ts:236` | Убирает из outstanding/overdue/по срокам. |
| `calendar` (платёжный календарь) | `operationsRepo.ts:269` | Убирает из бакетов обязательств. |
| `supplierScores` (overdue-штраф) | `operationsRepo.ts:183` | Не штрафует поставщика за «просрочку», которой нет. |

**НЕ трогаем** отчёты о тратах (`operationsRepo.reports` — monthly_spend/document_types/coverage): накладная, оплаченная сами, — это всё равно реальный расход, из аналитики трат её убирать нельзя.

## 5. Тестирование

Правило 17 CLAUDE.md: тесты только на `127.0.0.1`, `DB_NAME` c `test`.

- Миграция 55 идемпотентна (повторный прогон — no-op через `hasColumn`); бэкфилл ставит `read_at` существующим.
- `POST /:id/read {read:true|false}` — ставит/снимает `read_at`; owner-scoped (чужой id → 404/403).
- `GET /:id` владельцем при `read_at IS NULL` → проставляет `read_at`; повторный GET не меняет уже стоящий; не-владелец не трогает.
- `POST /:id/paid-externally {value}` — тумблер.
- `sberOverduePredicate`: накладная с `paid_externally=1` НЕ попадает в overdue (ни в SELECT-флаг, ни в cron-выборку) — расширить `tests/database/sberOverdue.test.ts`.
- `sberUnsent`: paid_externally исключён из счётчика.
- `operations` forecast/calendar: paid_externally исключён из обязательств; reports — остаётся в тратах.

## 6. Вне области

- «Способ оплаты» как перечисление (наличные/карта/…) — только булев флаг `paid_externally` (YAGNI).
- Кнопку «→ 1С» не меняем.
- `read_at` — глобально на накладную (аккаунт = компания, отдельного per-user read нет).
- Массовые действия (пометить всё прочитанным) — не сейчас.
