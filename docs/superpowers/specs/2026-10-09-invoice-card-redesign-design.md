# Карточка накладной «по шагам» и симметричный список — дизайн

Дата: 2026-10-09. Статус: утверждено владельцем («B — шаги, рядом с кнопкой скан маленькое превью», затем «всё делай»).
Макеты: `.superpowers/brainstorm/17651-1791573689/content/layout-v2.html` (варианты A/B/C), `b-detail-v2.html` (вариант B подробно).

## Зачем

В карточке накладной до товаров шли четыре блока подряд («Проверка документа», сетка реквизитов с галочками, форма Сбербанка, реквизиты поставщика) и 9–12 одинаковых кнопок; главное действие терялось, были видны служебные коды (`счет_на_оплату`, `posted`, имя файла, `GPT`), строки товаров раздувались подсказками пересчёта. Владелец в карточке: сверяет с фото и правит строки, отправляет в 1С, оплачивает через Сбер. Пересканирование и добавление страниц — редко.

Успех: открыв накладную, сразу видно, что это за документ, в каком он шаге и что делать дальше (одна главная кнопка); товары компактны; всё остальное — в один клик. Ни одна функция не пропадает. Сервер и API не меняются.

## Карточка

Сверху вниз:

1. **Шапка.** «← Накладные», заголовок «№ X от ДД.ММ.ГГГГ», строка «Поставщик · сумма · НДС · N позиций»; справа — соседние накладные (←/→), превью скана (первый лист; PDF/XML — значок) с подписью «Скан · N листов» и меню «⋯». Особые состояния — плашкой у заголовка: дубликат, ошибка распознавания, ждёт GPT, эталон.
2. **Предупреждения** — существующие баннеры (дубликат, «похоже на ту же накладную», сдвиг строк, цена выше обычной) под шапкой, без изменений по смыслу.
3. **Три шага** в ряд, равной ширины:

| Шаг | Состояния | Кнопка/текст на шаге |
|---|---|---|
| 1. Сверка с оригиналом | `current` (k из 6) / `done` (6 из 6) | — |
| 2. Отправка в 1С | `idle` → `queued` → `done`; `error`; `blocked` (распознавание не завершено, дубликат) | «Отправить в 1С» / «Ждёт загрузки в 1С» / «✓ В 1С: <документ>» / «1С не приняла» |
| 3. Оплата в СберБизнес | `off` (Сбер не подключён) / `idle` / `draft` / `bank` / `paid` / `failed` / `external` | «Создать платёжку» / «Черновик · ждёт подписи» / «✓ Оплачено» |

Под шагами — **панель выбранного шага** (по умолчанию первый незавершённый; нажатие на шаг открывает его панель):
- *Сверка:* шесть реквизитов со значениями (Номер, Дата, Поставщик, Сумма, НДС, Ставки НДС); нажатие на неотмеченный — открыть скан на этом реквизите и подтвердить (как раньше `InvoiceReview.verify`), на отмеченный — снять отметку. Ниже — замечания проверки (как раньше) и ссылки: «Открыть скан для сверки» (главная), «Сравнить с прошлой поставкой», «Изменить реквизиты», «Следующая на проверку →».
- *1С:* состояние, номер документа 1С / ошибка 1С, сколько новых товаров будет создано, «Отозвать», «Сбросить статус».
- *Оплата:* прежний блок Сбера (сумма и назначение, гейт «сверено 6 из 6», статус платежа, проверить статус, шаблон, удалить черновик) в компактной вёрстке.

Отправка в 1С до сверки разрешена (как сейчас); платёжка требует сверки 6 из 6 (как сейчас, запрет на сервере).

4. **Вкладки:** «Товары · N», «Поставщик и банк» (ИНН, БИК, счета, адрес, привязка поставщика; без служебных кодов — тип документа и статус 1С переводятся в слова), «История» (журнал правок; внизу сворачиваемый «Текст распознавания» / «Данные XML»).
5. **Товары:** компактная строка — № · «как в накладной» + под ним позиция 1С (выбор позиции на месте, как раньше) · количество (редактируется на месте; пересчёт одной серой строкой под ним) · цена · сумма · НДС · «⋯» строки. Проблема строки — меткой у названия («цена +12%», «нет позиции 1С», «нужен вес»). В меню строки: «Показать на скане», «Как в накладной», «Пересчитать», «Запомнить пересчёт», «Удалить строку». Под таблицей — «+ Добавить строку» и «НДС всем строкам».
6. **Скан — панель справа** (≈46% ширины, таблица остаётся рядом; на узком экране — поверх, на весь экран). Открывается превью, «Открыть скан для сверки», нажатием на реквизит, «Показать на скане». Внутри — прежний режим сверки `InvoiceReview` (листы, масштаб, выделения ИИ, «Найти на листе», «Выделить вручную», правка значения) плюс поворот листа. Для PDF и XML — сам документ (открыть PDF / данные XML).

**Меню «⋯»** (только применимые пункты): Пересканировать фото / Перечитать XML · Добавить страницы · Подобрать недостающие позиции 1С · Подобрать позиции 1С заново · Подобрать позиции ИИ · Подтвердить все позиции 1С · Изменить реквизиты · Сравнить с прошлой поставкой · Отметить эталоном / Убрать из эталонов · Сбросить статус «В 1С» · Удалить накладную (красным, последним).

## Список накладных

- Четыре карточки сводки и ряд вкладок дублировали друг друга. Остаётся один ряд из **пяти равных карточек-фильтров**: Все · Требуют внимания · Готовы к отправке · В очереди 1С · Без платёжки (число крупно, подпись мелко, выбранная — с рамкой).
- Таблица: Документ (номер, дата) · Поставщик и замечания (все замечания строки — одной строкой под поставщиком) · Сумма (вправо, табличные цифры, «в т.ч. НДС») · 1С · Оплата · действие. Колонки «1С» и «Оплата» одинаковой ширины, статусы — одинаковые плашки «точка + текст» (серый — нет, синий — в работе, зелёный — готово, янтарный — внимание, красный — ошибка), подпись мелко под плашкой. Кнопка действия — одной ширины во всех строках.

## Что не меняется

API, сервер, права, гейты (сверка 6/6 для Сбера), правила пересчёта, поведение массовых действий. Все прежние действия доступны (см. меню). Идентификаторы элементов, на которые опираются модули (`invoice-items-tbody`, `invoice-sber-section`, `invoice-source-workspace`, `invoice-comparison`, `invoice-tab-history`, …), сохраняются.

## Проверка

- Модульные тесты (vitest, `tests/frontend/invoiceCard.test.ts`, скрипт в `vm`): состояния шагов для всех статусов, выбор шага по умолчанию, состав меню «⋯» (XML/фото, отправлена/нет, эталон), «значения» реквизитов.
- Предпросмотр на реальных данных (статика из ветки + `/api` прода только на чтение) на накладных: распознана, на проверке, в очереди 1С, в 1С, ошибка 1С, с платёжкой (черновик/оплачено), дубликат, XML, PDF, многостраничная; ширина 1440 / 1024 / 390, без горизонтальной прокрутки.

## Риски

- В рабочей папке лежит чужая незакоммиченная работа «полнота накладной» (`completeness`) в тех же файлах (`invoices.js`, `invoice-review.js`). Редизайн сделан в отдельной ветке от `HEAD`; при слиянии их баннер «снята не полностью» встаёт в блок предупреждений, а запрет «Отправить в 1С» — в состояние шага 2 `blocked`.
