# TableCV — браузерная детекция ячеек таблицы (beta)

**Дата:** 2026-06-24
**Статус:** дизайн утверждён, готов к плану реализации

## Цель

Отдельный исследовательский эксперимент внутри ScanFlow: новая **beta-вкладка**, которая
по фото счёта/накладной классическим CV (OpenCV) находит **таблицу товаров**, восстанавливает
её сетку ячеек, читает текст в каждой ячейке (OCR) и **наглядно визуализирует** результат
поверх фото. Прод-пайплайн (Claude API / Google Vision) не затрагивается.

Документ-образец: печатный счёт с чёткой разлиновкой таблицы товаров (наклонённое/слегка
изогнутое фото). На таблице есть объединённые ячейки («Итого», «В том числе НДС», шапка таблицы).

## Решения (зафиксированы при брейнсторминге)

- **Размещение:** новая beta-вкладка в существующем vanilla-JS SPA. Прод-пайплайн не трогаем.
- **Метод детекции:** классический OpenCV — морфологическая детекция линий, без обучения, без GPU.
- **Среда выполнения:** `opencv.js` (WASM) **в браузере**. Фото не покидает клиент. Деплой без изменений.
- **Объём v1:** геометрия ячеек **+ OCR текста в ячейках** (Tesseract.js, rus+eng).
- **Зона v1:** **только таблица товаров.** Шапка/подвал (ИНН, КПП, банк, Счёт №/дата, Итого, НДС,
  подписи) — отдельный этап в будущем (там нет сетки → задача детекции текстовых блоков, не для чистого OpenCV).

## Архитектура

### Конвейер обработки (целиком в браузере)

```
фото → downscale (рабочий размер, запоминаем масштаб)
     → grayscale → adaptive threshold (борьба с тенью/бликом)
     → поиск рамки таблицы (крупнейший прямоугольный контур) → warpPerspective (выравнивание наклона/изгиба)
     → морфология: длинное горизонт. ядро → гор. линии; верт. ядро → верт. линии
     → координаты линий → сетка ячеек (алгоритм C) с merge объединённых ячеек
     → координаты ячеек обратно в исходное разрешение
     → по каждой ячейке: вырезка из выровненного фото → Tesseract.js (rus+eng)
     → overlay на canvas + таблица результата + экспорт JSON
```

### Алгоритм восстановления сетки

Выбран **вариант C: координаты линий + проверка границ**.

1. Из масок линий извлекаем X-позиции вертикальных и Y-позиции горизонтальных линий
   (кластеризация близких линий в одну координату).
2. Декартово произведение координат → сетка кандидатов-ячеек (строки × столбцы).
3. Соседние ячейки **объединяем там, где разделяющей линии фактически нет** (проверяем
   наличие отрезка линии между двумя соседними пересечениями). Это корректно обрабатывает
   объединённые ячейки.

Отвергнутые альтернативы:
- **A. Кластеризация точек пересечения** — чувствительна к разрывам линий.
- **B. Поиск контуров ячеек** (`findContours`) — плохо переносит объединённые ячейки и шум.

### Модули (изолированные, чёткие границы)

Всё клиентское, в `public/js/tablecv/`:

| Модуль | Что делает | Зависит от |
|--------|-----------|-----------|
| `preprocess.js` | загрузка, downscale, grayscale, threshold, перспективная коррекция; возвращает выровненный mat + матрицу преобразования + масштаб | opencv.js |
| `gridDetect.js` | линии → ячейки (алгоритм C, merge). **Ядро вынесено в чистые функции** на массивах координат | opencv.js (тонкий адаптер) |
| `cellOcr.js` | вырезки ячеек → Tesseract.js, ограничение параллелизма, прогресс | tesseract.js |
| `overlay.js` | отрисовка рамок/индексов/текста на canvas, подсветка ячейки по наведению | — |
| `export.js` | сборка JSON и HTML-таблицы из ячеек+текста | — |
| `tablecv.js` | контроллер вкладки: загрузка фото, запуск, прогресс, debug-ползунки, рендер результата | все выше |

Граница каждого модуля: вход/выход — простые структуры (mat, массивы координат, массив ячеек
`{row, col, rowSpan, colSpan, x, y, w, h, text}`), без скрытого общего состояния.

### Интеграция в SPA

- Новая секция в `public/app.html` + hash-роут `#/tablecv`.
- Пункт меню навигации с меткой **beta**.
- `opencv.js`, `tesseract.js` и `rus.traineddata` **вендорятся в `public/vendor/`**
  (прод за HTTP-прокси → CDN ненадёжен) и **лениво грузятся только при первом открытии вкладки**
  (opencv.js ~8 МБ; не тащим на остальных страницах).
- **Сервер не меняется** — ни новых роутов, ни миграций, ни зависимостей в `package.json` сервера.

## Debug-режим

Для исследовательской ценности — панель параметров:
- Ползунки: размер блока adaptive-threshold, минимальная длина линии (% ширины/высоты).
- Переключатели слоёв: показать бинаризацию / маску линий / точки пересечения / итоговые ячейки.
- Тумблер «только геометрия, без OCR» (быстрый прогон).

## Обработка ошибок

- **Таблица не найдена** (нет уверенной сетки) → сообщение + показ найденных линий (видно, почему не вышло).
- **opencv/tesseract не загрузились** → понятная ошибка + кнопка повтора.
- **Очень большое фото** → cap рабочего разрешения (downscale), маппинг координат обратно.
- **Медленный OCR** → прогресс по ячейкам + возможность отключить OCR.

## Тестирование

- **Юнит-тесты (vitest, без браузера/opencv):** ядро `gridDetect` — кластеризация линий,
  сборка ячеек из координат, merge объединённых ячеек — как чистые функции на числовых массивах.
- **Визуальная проверка:** standalone-страница, прогоняющая фото-образец и показывающая overlay (глазами).
- WASM/DOM-слой автоматически не тестируем — изолирован в тонкие адаптеры внутри `preprocess`/`cellOcr`.

## Вне объёма v1 (явно)

- Детекция полей шапки/подвала (ИНН, Счёт №, Итого, НДС, подписи).
- Server-side обработка, эндпоинты, миграции.
- Замена/дополнение прод-OCR результатами TableCV.
- ML-модели (Table Transformer / PaddleOCR) — возможный будущий fallback для безграничных таблиц.
