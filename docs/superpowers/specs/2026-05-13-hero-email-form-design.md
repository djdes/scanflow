# Hero email-form для повышения конверсии лендинга

## Контекст

Сейчас hero на главной [public/index.html:125-176](../../../public/index.html#L125-L176) содержит две CTA-кнопки:
- **Начать бесплатно** (синяя, `data-action="hero-register"`) → открывает модалку с email-полем → `POST /api/auth/register-email` → magic-link на почту.
- **Что можно сканировать →** (outline) → якорь на секцию `#scan-types`.

Регистрация уже email-only ([landing.js:692-733](../../../public/js/landing.js#L692-L733)): пользователь вводит email, сервер генерит username/password/magic-token и отсылает welcome-email. Auto-login отсутствует — нужно пройти по ссылке из письма.

**Проблема:** между «увидел сайт» и «ввёл email» лежит клик на кнопку → открытие модалки → ввод email → отправка. Лишний шаг режет конверсию.

**Цель:** вынести email-поле прямо в hero, чтобы пользователь мог зарегистрироваться без открытия модалки.

## Решение

### Структура CTA в hero

Сверху вниз:

1. **Email-форма** (новая, primary) — горизонтальный flex: `[email-input] [Получить доступ]`.
2. **Кнопка `Попробовать`** (secondary, поменьше) — переименованная текущая `Начать бесплатно`. Открывает существующую модалку регистрации (поведение прежнее).
3. Trust-список (`Без карты`, `30 секунд`, `Серверы в РФ`) — без изменений.

**Удаляется:** ссылка `Что можно сканировать →`.

### Поведение формы

- HTML5 `<input type="email" required>`, autocomplete=email, placeholder=`ваш@email.com`.
- Submit по Enter и по клику.
- Reuse существующего endpoint `POST /api/auth/register-email` с `{ email }`.
- На время запроса: кнопка disabled, текст → `Отправляем…` (паттерн как в [landing.js:701-703](../../../public/js/landing.js#L701-L703)).
- **Успех**: вызываем `showMailSentView(email, 'register')` ([landing.js:783](../../../public/js/landing.js#L783)) — открывается существующая модалка логина в state `mail-sent` с инструкциями «проверьте почту, ссылка действует 24 часа». Единый UX с регистрацией из модалки.
- **Перед открытием mail-sent**: чистим onboarding-флаги в localStorage (копируем [landing.js:721-723](../../../public/js/landing.js#L721-L723)).
- **Ошибка** (4xx с body `{error}`, 5xx, network): красный текст под инпутом, кнопка возвращается в нормальное состояние.

### Стили

- Email-инпут: `var(--border)`, белый/полупрозрачный фон, focus — синий бренда. По высоте совпадает с `btn-primary`.
- Кнопка `Получить доступ` — `btn-primary` (сине-зелёный градиент). Без иконки upload — стрелка `→` или ничего.
- Группа `.hero-email-form` — `display: flex; gap: 8px; max-width: 480px; margin: 0 auto;` на desktop.
- На mobile (`<640px`) — `flex-direction: column; gap: 12px;`, оба элемента full-width.
- Кнопка `Попробовать` — оставить `btn-primary` (как сейчас), но возможно уменьшить визуальный вес: убрать иконку upload или сделать ghost-вариант. Финально решим на этапе CSS.

### Файлы под изменение

- [public/index.html:154-160](../../../public/index.html#L154-L160) — переразметка `.hero-cta`: добавить `<form class="hero-email-form">`, переименовать кнопку, удалить outline-ссылку.
- [public/css/landing.css](../../../public/css/landing.css) — новый класс `.hero-email-form` + responsive стек на mobile, стили инпута.
- [public/js/landing.js](../../../public/js/landing.js) — новый обработчик `submit` для `.hero-email-form` (fetch + showMailSentView + onboarding flags cleanup). Reuse существующего обработчика `[data-action="hero-register"]` для кнопки `Попробовать` (label поменяется в HTML, JS не трогаем).

## Что НЕ делаем (out of scope)

- Не вводим JWT/cookie-сессии — magic-link flow остаётся.
- Не меняем endpoint `/api/auth/register-email`.
- Не трогаем разметку и логику модалки логина/регистрации (нужна для повторных открытий).
- Не добавляем capcha/honeypot/rate-limit для `/api/auth/register-email` — отдельная фича, если будет спам.
- Не трогаем секцию `#scan-types` сама по себе — только удаляем ссылку на неё из hero.

## Риски и проверки

1. **Mobile keyboard pop-up:** на iOS/Android при фокусе на email-инпут вылезает клавиатура → hero визуально сжимается. Это ожидаемо для CTA-формы, проверяем что текст H1 не «прыгает» и layout не ломается.
2. **Дублирование с модалкой:** если пользователь ввёл email в hero, а форма открыла модалку в state `mail-sent` — он не должен видеть свой email пустым. `showMailSentView(email, 'register')` уже подставляет email — проверяем.
3. **Двойной submit:** если пользователь сабмитнёт hero-форму, потом откроет модалку и сабмитнёт там снова с тем же email → сервер должен корректно обрабатывать (idempotent или 409). Это вне scope, но стоит проверить вручную.
4. **Анти-enumeration:** `/api/auth/register-email` сейчас, видимо, возвращает разный ответ для существующего/нового email. Не наша забота в этой задаче, но если будет видно — флагуем.

## Критерии готовности

- На главной в hero видна форма `[email] [Получить доступ]` и под ней кнопка `Попробовать`.
- Ссылка `Что можно сканировать →` удалена из hero.
- Ввод корректного email + клик `Получить доступ` → модалка открывается в state `mail-sent` с подставленным email, в почту приходит welcome-письмо с magic-link.
- Невалидный email → браузерная валидация HTML5 блокирует submit.
- Ошибка сервера → красное сообщение под инпутом, форма не «зависает».
- Mobile (≤640px) — инпут и кнопка в столбик, full-width, layout не ломается.
- Кнопка `Попробовать` открывает существующую модалку регистрации (поведение прежней `Начать бесплатно`).
