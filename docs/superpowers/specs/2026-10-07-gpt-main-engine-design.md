# GPT по подписке ChatGPT — единственный ИИ-движок ScanFlow

**Дата:** 2026-10-07
**Статус:** дизайн согласован с владельцем, к реализации.
**Предыдущий шаг:** [2026-10-06-gpt-vision-mode-design.md](2026-10-06-gpt-vision-mode-design.md) — режим `gpt` для чтения фото (выкачен 06.10, коммит `0d3244e`).

## Зачем

Аккаунта Claude больше нет. Всё, что в ScanFlow делает ИИ, должно идти через подписку ChatGPT,
подключённую в самом ScanFlow. 07.10 прод уже переключён в режим `gpt`: фото читает GPT. Но в Claude
по-прежнему ходят PDF, подбор позиций 1С, ночной разбор правок, помощник, «Заполнить по фото»,
подсветка источника, а `/health` требует ключ Anthropic.

Проверка 06–07.10 на 10 накладных очереди показала: GPT читает не хуже Claude Sonnet 5 на том же
конвейере. Один случай GPT читает лучше — срезанную вторую строку названия («10л/9,6кг»).

## Решения владельца

1. **Только GPT, всегда.** Claude в работе не вызывается нигде. Автоматического перехода на Claude нет.
2. **Когда GPT недоступен** (лимит подписки, нужен повторный вход, OpenAI или прокси не отвечают):
   накладные ждут, админу уходит сообщение в Telegram, после восстановления всё распознаётся само.
3. **Код Claude остаётся** за шлюзом, но в интерфейсе его нет. Вернуть можно только ключом
   Anthropic и режимом `claude_api` через API настроек или базу (правило 26: прежние пути не удалять).
4. **Один ИИ-шлюз** для всех вызовов (подход A из трёх).
5. **Страница «Настройки» — чище:** только GPT, подсказки в одну строку, без технических слов.

## Не входит

- Автоматический переход на Claude или другой движок.
- Ключ OpenAI API: работа идёт только по подписке.
- Изменение логики эталонов, ролей, компаний, движков v2 — только тексты на странице.
- Режимы `hybrid` и `dispatcher` остаются в коде, но со страницы уходят.

## 1. ИИ-шлюз — `src/ai/`

```ts
// src/ai/gateway.ts
export type AiInput =
  | { type: 'text'; text: string }
  | { type: 'image'; mediaType: 'image/jpeg' | 'image/png' | 'image/webp'; data: string /* base64 */ };

export interface AiRequest {
  purpose: string;              // для логов и расхода: 'ocr_main', 'ocr_numbers', 'map_items', …
  system: string[];             // блоки инструкций; у Claude — с cache_control, как сейчас
  content: AiInput[];
  effort?: 'low' | 'medium' | 'high';
  imageDetail?: 'low' | 'high';
  maxOutputTokens?: number;
  timeoutMs?: number;
}

export async function aiStructured<T>(req: AiRequest & { schema: object; schemaName: string }): Promise<AiResult<T>>;
export async function aiText(req: AiRequest): Promise<AiResult<string>>;
export async function aiEngineState(): Promise<AiEngineState>; // движок, модель, доступен ли, причина, время сброса

export class AiUnavailableError extends Error {
  reason: 'not_connected' | 'reauth_required' | 'rate_limited' | 'network';
  retryAtMs: number | null;     // для rate_limited — время сброса лимита
}
```

- **Выбор движка.** `analyzer_config.mode === 'claude_api'` — Claude (`claude_model`, ключ из
  настроек или `.env`). Любой другой режим — GPT (`gpt_model`, по умолчанию `gpt-6.1-sol`).
  Модуль, решающий «GPT или Claude», один. Остальной код имён движков не знает.
- **Реализации.** `src/ai/gptEngine.ts` — поверх `codexRespond` (подписка, строгая схема
  `toStrictSchema`, `store: false`). `src/ai/claudeEngine.ts` — нынешние вызовы SDK, перенесённые
  без изменений поведения (кэш системных блоков, адаптивное размышление).
- **Недоступность против плохого ответа.** `AiUnavailableError` бросается только когда
  до модели не достучаться:
  - нет подключения, нужен повторный вход или лимит — из `ChatgptUnavailableError`;
  - сеть, прокси, таймаут соединения, 5xx после повторов, 403 от Cloudflare.

  Неразборчивый JSON, нарушение схемы или обрыв ответа (`incomplete`) — обычная ошибка: накладная
  получает «ошибку», как сейчас.
- **Повторы.** Нынешний `withRetry` переезжает в шлюз; `AiUnavailableError` не повторяется.

## 2. PDF — страницы в картинки

- `src/ocr/pdfPages.ts`: `pdfToImages(pdfPath, { maxPages: 10, dpi: 200 }) → string[]` (временные JPEG).
  Работает на `pdfjs-dist` (legacy-сборка для Node) и `@napi-rs/canvas`, без системных программ:
  на сервере нет SSH-доступа, ставить poppler некуда.
- Страницы читаются так же, как многостраничная фотонакладная: каждая страница — отдельный
  вызов, потом склейка. Поворот не определяется: страница PDF уже стоит прямо.
- Больше 10 страниц — читаются первые 10, в накладной предупреждение.
- Ту же функцию используют приём, перераспознавание очереди и эталоны.
- «Заполнить по фото» у поставщика: PDF — первая страница.

## 3. Когда GPT недоступен

### Накладная ждёт

- Новый статус **`waiting_ai`**, в интерфейсе — «Ждёт GPT». Колонка `status` — `VARCHAR(32)`,
  миграция не нужна.
- `processFile` при `AiUnavailableError`:
  - ставит `waiting_ai`, фото кладёт в `processed/`, как при успехе — оттуда его берёт `reprocessInvoice`;
  - не шлёт `recognition_error` и письмо об ошибке, не трогает `recovery_attempts`.
- Восстановление после сбоя процесса (`crashRecovery.ts`) строки `waiting_ai` не трогает: они не «застряли».
- Ручное «Пересканировать»:
  - сначала `aiEngineState()`; если GPT недоступен — 503 «GPT сейчас недоступен: причина», накладная не меняется;
  - если GPT упал посреди работы — `waiting_ai`.

### Возобновление — `src/services/aiResume.ts`

- **Когда проверяет:**
  - раз в 5 минут;
  - сразу после успешного входа в ChatGPT и успешной «Проверки связи»;
  - через 30 секунд после времени сброса лимита.
- **Как распознаёт:** если GPT доступен, берёт `waiting_ai` по возрастанию id по всем компаниям,
  **строго по одной** (правило 21), через `waitForRecognitionIdle` и `reprocessInvoice`.
- **После успеха** — то же, что в конце `processFile`: уведомления «распознана» и проверки цен,
  хуки автоотправки в 1С и Сбер.
- **Если ошибка:**
  - снова `AiUnavailableError` — накладная остаётся `waiting_ai`, проход прекращается;
  - любая другая ошибка — `error` с обычным уведомлением об ошибке.
- Один проход за раз — флаг в памяти. PM2 держит один процесс.

### Telegram

- Кому: всем пользователям с `role='admin'`, у которых настроен Telegram. Подписка общая на платформу.
- **GPT остановился** — `sendOwnerAlert(adminId, 'ai_unavailable', текст, 6)`: не чаще раза в 6 часов,
  пока сбой длится. В тексте:
  - причина и что сделать: «Лимит подписки ChatGPT до 18:40 МСК», «ChatGPT просит войти заново:
    Настройки → Войти по коду» или «OpenAI или прокси не отвечают»;
  - сколько накладных ждёт.
- **GPT снова работает** — `'ai_resumed'`: «GPT снова работает, распознаю N накладных». Уходит,
  только если последнее `ai_unavailable` новее последнего `ai_resumed` (по `owner_alerts`).
- Отправка никогда не бросает (правило 9).

### Статус для пользователей

- `GET /api/ai/status` (любой пользователь): движок, модель, доступен ли, причина простым текстом,
  время сброса, число `waiting_ai` своей компании.
- Над списком накладных, если GPT недоступен или есть ждущие: «Распознавание приостановлено:
  причина. Ждут: N».

### Остальные функции при недоступном GPT

| Функция | Поведение |
|---|---|
| Задачи очереди «перераспознать» и «подобрать позиции ИИ» | пауза с причиной; возобновление продолжает их с того, что не сделано |
| Ночной разбор правок | ИИ-советчик пропускает ночь; правила из разбора без ИИ создаются как обычно |
| Помощник | нынешний ответ без ИИ |
| «Заполнить по фото», подсветка источника | 503 «GPT сейчас недоступен: причина» |
| ИИ-подбор позиций для XML-накладной и перепривязка | правила и похожие названия, как сейчас при сбое ИИ |

## 4. `/health`

- Ключ Anthropic проверяется только в режиме `claude_api`.
- Новая строка `checks.ai_engine` — `{ ok, detail }`, например «gpt-6.1-sol: работает» или
  «лимит до 18:40». На итоговый `status` она **не влияет**: выкладка ждёт `"status":"ok"`
  (`deploy.yml`), и лимит подписки не должен ломать выкладку.

## 5. Промпт: названия как напечатано

В «ТОЧНОСТЬ НАЗВАНИЙ» (`claudeApiAnalyzer.ts`):
- строка «Бренды/производителя/артикул из name убирай.» → «Название переписывай как напечатано —
  с брендом, производителем и артикулом»;
- пример «Горбуша…» — без вычёркивания бренда.

Зачем: подтверждённые сопоставления и ключи товара сохранены под названия «как напечатано».
Claude это правило почти не выполнял, а GPT выполняет. Если правило оставить, у GPT часть
сопоставлений не найдётся. Правило сопоставления с каталогом («бренд можно игнорировать при
выборе позиции») не меняется.

## 6. Страница «Настройки»

Заголовок «Настройки», без подзаголовка. Подсказки — одна строка, без `approved_for_1c=1`,
`verified=1`, «pull'е», «fuzzy», «LLM».

1. **Распознавание**:
   - строка состояния «GPT по подписке ChatGPT — подключено (почта, Pro)» или «лимит до …»,
     «нужно войти заново»;
   - кнопки «Проверить связь», «Отключить», без подключения — «Войти по коду», код показывается тут же;
   - **Модель**: GPT-6.1 Sol (основная), GPT-6 Luna (быстрее, бережёт лимит), GPT-6 Astra (точнее,
     тратит больше лимита);
   - переключатель **«Подбирать позиции 1С при распознавании»** — «GPT выбирает товар из справочника
     1С сразу при чтении фото»;
   - если в базе режим не `gpt`: строка «Сейчас включён другой режим» и кнопка «Перейти на GPT»;
   - уходят: выбор из четырёх режимов, ключ Anthropic, модель Claude, поля ProjectsFlow.
2. **Автоматизация** — переключатели сохраняются сразу:
   - «Сразу отправлять в 1С» — «Распознанная накладная без ошибок сразу уходит в 1С»;
   - «Сразу создавать платёжку в Сбере» — «Черновик создаётся только для подтверждённых поставщиков».
3. **Поставщики** — ключ DaData: «Нужен для кнопки „Заполнить по ИНН“ в карточке поставщика».
   Своя кнопка «Сохранить».
4. **Проверки и пересчёт** (бывшие «Движки v2») — свёрнуто по умолчанию, подсказки в одну строку
   (`ENGINE_FLAG_INFO`).
5. **Эталоны, команда и роли, компании** — только админ; логика прежняя, тексты короче.

API настроек не сужается: `PUT /api/settings/analyzer` по-прежнему принимает все режимы — это
рычаг возврата.

## 7. Тесты (vitest, только `scanflow_test`)

- **Шлюз:**
  - в режиме `gpt` Claude SDK не вызывается ни при каких условиях, включая ошибки GPT;
  - ошибки GPT распознаются верно: недоступность → `AiUnavailableError` с причиной и временем
    сброса, плохой ответ → обычная ошибка;
  - в режиме `claude_api` — Claude.
- **Ожидание:** при недоступности `processFile` даёт `waiting_ai`, нет `recognition_error`, нет
  письма, фото в `processed/`.
- **Возобновление:**
  - одна накладная за раз, по возрастанию id;
  - повторная недоступность прекращает проход;
  - после успеха — уведомления и автоотправка;
  - `crashRecovery` не трогает `waiting_ai`.
- **Telegram:** не чаще раза в 6 часов; «снова работает» только после «остановился».
- **PDF:** двухстраничный тестовый PDF → две картинки, лимит страниц.
- **Места на шлюзе:** каждое из таблицы раздела 1 вызывает шлюз (мок), а при недоступности
  ведёт себя по таблице раздела 3.
- **`/health`:** `ai_engine` не влияет на итоговый `status`; в режиме `gpt` ключ Anthropic не нужен.
- **Промпт:** снимок — строки про удаление брендов нет.
- **Страница:** проверка в браузере на 1280, 390 и 320 px, `scrollWidth` не больше ширины экрана
  (правило 38).

## 9. Риски

- **Условия OpenAI.** Подписка ChatGPT рассчитана на личное использование, адрес Codex
  неофициальный и может измениться. Весь доступ — в `codexClient.ts`, правка в одном месте.
- **Лимиты.** Около 28 накладных в месяц, 5–8 запросов на страницу, плюс ночной разбор и подбор
  позиций. На плане Pro запас большой. Исчерпание — это ожидание, а не потеря накладных.
- **Координаты подсветки** у GPT не проверены. Если будут неточны — остаётся ручное выделение.
- **PDF через картинки** теряет текстовый слой. Для сканов это то же самое, для «цифровых» PDF
  чтение по картинке 200 dpi достаточно (как у фото).
