# Сбер: TLS-сертификат — срок на виду и замена из кабинета

Дата: 2026-11-05. Запрос владельца: «чтобы никогда не нужно было продлевать».

## Что истекает в доступе к Sber API

| Что | Срок | Как держится |
|---|---|---|
| client_secret | бессрочный с 04.11.2026 | ничего не нужно |
| access_token | 60 минут | обновляется сервером |
| refresh_token | 180 дней с последнего использования | обновляется каждый час и ночью |
| **TLS-сертификат** (`.p12`) | **12 месяцев с выдачи** | **только человек** |

Документация Sber API («TLS-сертификат»): «Срок действия сертификата — 12 месяцев
с даты выдачи». Выпуск — в личном кабинете Sber API («Сгенерировать сертификат»)
или через поддержку по CSR; метода API нет (`crypto/cert-requests` — сертификаты
подписи сотрудников, не TLS). Новый сертификат старые не отменяет. Значит, совсем
без человека нельзя; цель — раз в год пара минут, заранее и без SSH.

До этого изменения срок сертификата нигде не отслеживался: файл на сервере
(`SBER_TLS_PFX` + пароль в `.env`), и когда он истечёт, платёжки молча перестанут
создаваться.

## Решение

1. **Срок на виду.** Сервер читает срок из `.p12` (`tls.createSecureContext` →
   `context.getCertificate()` → `X509Certificate.validTo`; проверено на Node 20.10
   и 25) и показывает на `/#/sber`: «TLS-сертификат до …, осталось N дн.».
2. **Напоминания.** Ночью (04:15, вместе с обслуживанием токенов) при сроке ≤ 60 дней —
   Telegram владельцам компаний с подключённым Сбером (`sendOwnerAlert`, вид `sber_tls`)
   и письмо на `MAIL_TO`. Частота: ≤ 60 дн. — раз в 14 дней, ≤ 30 — раз в неделю,
   ≤ 7 — каждый день.
3. **Замена из кабинета (admin).** `POST /api/sber/tls-cert` `{pfx_base64, password}`:
   разбор файла и пароля → не истёк и уже действует → проверка связи со Сбером этим
   сертификатом (`client-info` с токеном компании админа) → сохранить. Не прошёл —
   400/502 с причиной, текущий сертификат не трогается.
4. **Хранение.** `sber_app` (миграция 94): `tls_pfx_enc`, `tls_pass_enc` — зашифрованы
   `sealSecret` с отдельными purpose (ключ из `JWT_SECRET`, как client_secret);
   `tls_valid_to` (UTC), `tls_subject`, `tls_set_at`. Наружу и в логи файл и пароль
   не отдаются.
5. **Какой сертификат в работе.** `sberClient` берёт из БД и из файла `.env` тот,
   что действует дольше; кэш сбрасывается при загрузке нового — без перезапуска.
   Положили новый файл на сервер руками — он тоже подхватится, если свежее.

## Не делаем

- Автовыпуск сертификата: у Сбера нет для этого API.
- Удаление сертификата из БД кнопкой: старый просто вытесняется более свежим.
