# Карточка накладной «по шагам» и симметричный список — план

> Исполнение: Native (владелец: «всё делай»). Спек: `docs/superpowers/specs/2026-10-09-invoice-card-redesign-design.md`.

**Цель:** карточка накладной по варианту B (шапка с превью скана, три шага, панель шага, компактные товары, скан справа, меню «⋯») и список с пятью равными карточками-фильтрами и одинаковыми статусами.

**Архитектура:** новый модуль `public/js/invoice-card.js` (`InvoiceCard`) рисует шапку, шаги, панели и меню и хранит открытый шаг; чистые функции (`stepStates`, `defaultStep`, `menuItems`, `requisites`) тестируются в `vm`. `invoices.js` отдаёт ему данные накладной и рисует строки товаров в новом виде; `invoice-review.js` рисует панель сверки и режим скана в правой панели; `sber.js` — компактный блок оплаты в панели шага 3. Сервер не меняется.

**Стек:** vanilla JS (без сборки), CSS в `public/css/style.css` (новый раздел в конце), vitest + `node:vm` для чистых функций.

## Global Constraints

- Весь видимый текст — по-русски, без служебных кодов.
- Шрифт Onest, токены `:root` из `style.css`; иконки — SVG, не эмодзи.
- Одна главная кнопка на экране; редкие действия — в «⋯».
- Сетка на телефоне — `minmax(0, 1fr)` (правило 38), без горизонтальной прокрутки на 390/360/320.
- Сервер и API не меняются; гейт Сбера (сверка 6/6) остаётся на сервере и в интерфейсе.
- Сохранить ID: `invoice-items-tbody`, `invoice-price-warning`, `invoice-items-toolbar`, `invoice-tab-history`, `invoice-ocr-text`, `invoice-photos-container`, `invoice-supplier-details`, `invoice-sber-section`, `invoice-decision`, `invoice-source-workspace`, `invoice-comparison`, `invoice-sibling-banner`, `invoice-nav`, `invoice-price-badges`.

## Review Focus

1. Накладная без фото (XML, PDF, удалённое по сроку фото) — превью и панель скана не ломаются, показывают документ или «файл удалён».
2. Дубликат — шаги 2–3 недоступны, остаётся баннер «Не дубликат / Удалить дубликат».
3. Сбер не подключён / нет реквизитов плательщика — шаг 3 «Подключите СберБизнес», без ошибок в консоли.
4. Переход между накладными стрелками ←/→ с открытой панелью скана — панель показывает скан новой накладной, а не прежней.
5. Узкий экран (390 px) — шаги в столбик, скан поверх на весь экран, без горизонтальной прокрутки.

## Задачи

1. **Чистые функции карточки** — `public/js/invoice-card.js` (`stepStates(inv, review, payment, sber)`, `defaultStep(states)`, `menuItems(inv)`, `requisites(inv)`), тест `tests/frontend/invoiceCard.test.ts`.
2. **Разметка и стили карточки** — `public/app.html` (`#invoice-detail`: шапка, предупреждения, шаги, панель шага, сравнение, тело: вкладки + правая панель скана), раздел CSS «Карточка накладной».
3. **Отрисовка карточки** — `InvoiceCard.render(data)`, меню «⋯», шаги и панели; `invoices.js:showDetail` зовёт его вместо прежних шапки/кнопок; гейт Сбера считается по состоянию, а не по чекбоксам.
4. **Строки товаров** — компактная строка, метки проблем, меню строки; убраны ссылки «Строка на фото ↗».
5. **Скан справа** — `invoice-review.js`: панель сверки в шаге 1, режим скана в правой панели (+ поворот листа), документы PDF/XML без фото; превью в шапке.
6. **Оплата в шаге 3** — компактная вёрстка `Sber.renderInvoiceSection`.
7. **Список** — пять карточек-фильтров вместо карточек и вкладок, одинаковые статусы 1С/оплаты, кнопка действия одной ширины.
8. **Проверка** — тесты, предпросмотр на реальных накладных всех состояний, ширины 1440/1024/390; CLAUDE.md; выкладка.
